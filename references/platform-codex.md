# Codex memory layout

Based on the OpenAI Codex documentation as of 2026-11. If what you find on disk does not match, trust the disk, say so in the report, and stay read-only.

## Store

- Memory lives under the Codex home directory: `$CODEX_HOME`, by default `~/.codex`.
- A fresh Codex home uses `memories_v2/`. If `memories/` already exists, Codex keeps using that one. Check both.
- Memories are off by default. They are enabled with `memories = true` under `[features]` in `config.toml`. If neither directory exists, report that there is no memory store; do not create one.
- The store is per machine. The documentation does not describe per-project or per-branch scoping, so judge the scope of each memory from its content.
- The files are generated by Codex in the background from earlier chats, as summaries and supporting evidence. Their names and roles are not documented. Inventory what is actually there; do not assume a layout.

## What this changes

- `scan` and `review` work as described in `SKILL.md`.
- The documentation says the files can be inspected but that hand editing should not be the primary way to control memory, and a later generation pass may rewrite them. For `cleanup`, `archive`, and `promote`, the default is therefore to report findings and propose actions. Edit generated files only when the user approves it after being told about this limitation.
- Controls to propose to the user instead of editing files:
  - `memories.use_memories` in `config.toml`: whether existing memories are injected into new sessions.
  - `memories.generate_memories` in `config.toml`: whether new chats can become memory.
  - `/memories`: memory use for the current chat only.
  - "Delete Codex memories" in the app settings: resets the whole store on that machine. It is destructive and the user performs it.
- `config.toml` is user configuration. Propose changes; do not edit it.
- Rules that must always apply belong in `AGENTS.md` or checked-in documentation, not in memory. When a memory is really such a rule, propose moving it there.
